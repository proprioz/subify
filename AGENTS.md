# Notes for AI coding agents

This project accepts contributions written with any AI tool, or none. The rules are the same for everyone and live in [CONTRIBUTING.md](CONTRIBUTING.md): read it before changing anything, and [README.md](README.md) for what the app is and how it is configured.

What an agent tends to get wrong here:

- **The non-negotiable principles** in CONTRIBUTING.md come first. If a task conflicts with one, don't build it: say so and propose an alternative.
- **Look at UI changes in a browser**, at 390×844, in light and dark mode, with whatever browser automation your tool offers (for example the Playwright MCP server). If none is available, say that the check was not done rather than skipping it silently.
- **Ask before adding a dependency**, and never bypass pnpm's `minimumReleaseAge`.
- **No test may reach the network**, and `fixtures:record` is the only script that contacts YouTube (a running dev server reads it too, for the channels in its catalog): don't run it unless asked.
- **Seeded channels must stay indistinguishable** from users' channels (docs/FEATURES.md, D15): no column, log or code path of their own.
- **Done means** `pnpm typecheck`, `pnpm test:all` and `pnpm build` pass.
- **Never deploy from your machine** (`wrangler deploy`, `wrangler d1 migrations apply --remote`): GitHub Actions deploys `main` once every check has passed (CONTRIBUTING.md, Deployment). Don't suggest a deploy by hand unless the user asks or CI can't.
- **Commits** are attributed to the person who makes them: no co-author or “generated by” lines for the tool.
